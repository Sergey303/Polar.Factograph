# Переключение Polar.DB.Typed на внешние индексы

Пока внешний индекс Polar.DB.Typed может возвращать неверное смещение для таблиц с `Guid`-ключом, приложение запускается в безопасном режиме:

```json
"PolarDb": {
  "ReadMode": "FullScan"
}
```

Оба пути чтения находятся в коде:

- `FullScan` — читает основную таблицу и фильтрует строки в памяти;
- `ExternalIndexes` — использует `DbSet.Find(...)` для троек, имён и полнотекстового поиска.

После исправления Polar.DB.Typed:

1. Обновить ссылку/версию Polar.DB в solution.
2. Выполнить `dotnet test` в Polar.DB.
3. Выполнить `dotnet test` в Polar.Factograph. Тест `Queries_ApplyCassetteVisibilityAndCompositePatterns` запускается в обоих режимах.
4. Поменять `PolarDb:ReadMode` на `ExternalIndexes` в:
   - `src/Polar.Factograph.Api/appsettings.json`;
   - `scripts/run/appsettings.json`.
5. Перезапустить API.
6. Через администрирование полностью пересоздать поколение Polar.DB, чтобы вторичные индексы были записаны исправленной библиотекой.
7. Проверить поиск и страницы ресурсов из нескольких кассет.
8. Запустить отдельную проверку ресурсов и троек и убедиться, что отсутствующих и лишних элементов нет.

Не переключать существующее поколение на `ExternalIndexes`, если исправление Polar.DB требует нового физического формата внешних индексов: сначала создать новое поколение.

После стабильной проверки режим `FullScan` и эту настройку можно удалить отдельным небольшим коммитом.
